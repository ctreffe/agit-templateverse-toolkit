# Utility Engineering Philosophy

Apply the AI Dev Template principles to independent reusable helpers: start
from maintainer intent, prefer the smallest maintainable solution, keep code
human-readable, document non-obvious effects and validate before success claims.
Repository evidence is durable memory; conversations are working context.
Keep small reviewable steps separate from intentional milestone closure.

Host changes follow Observe -> Explain -> Dry run -> Confirm -> Apply -> Verify
-> Remove. Privilege, persistent state and removal must be visible before use.
User-started affirmative action is required; installation, ACLs, OS identities
and synchronization settings retain their separately accepted boundaries.
Generic public recipes must never expose private governance or authenticated
state. Maintainer scope, compatibility, publication and risk acceptance remain
human-owned. A successful command is evidence, not proof of real-host safety.

## Template Mission

Support classical software projects and projects whose purpose depends on
substantial code-based tooling. Make software understandable, maintainable and
reviewable through a roadmap jointly managed by the maintainer and agent.

Work in a deliberate rhythm of bounded work packages, implementation,
validation and authorized commits. Versions and the changelog make completed
states and progress traceable. Interactive review-code supports maintainer
participation down to individual lines and engineering decisions. GitHub's
workflow and ChatGPT's GitHub integration, when available and authorized, are
important collaboration channels. Neither roadmap progress nor a successful
test substitutes for maintainer judgment or protected Git/release authority.

## Mission Ownership

This section owns the source template's mission. In a derived project, retain it
as the inherited workflow purpose; PROJECT_CONTEXT.md owns the maintainer's
concrete project mission, outcome and boundaries. Do not substitute the template
mission for that local purpose. Maintainer domain judgment remains decisive at
both levels. Disclose actual human-AI collaboration clearly in template and
project READMEs without exposing sensitive content. The local
[alignment method](COLLABORATION.md#mission-alignment) governs reviews and
retrospectives; mission drift requires a maintainer decision, not silent rewriting.
