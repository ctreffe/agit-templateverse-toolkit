# Utility Engineering Philosophy

Apply the AI Dev Template principles to independent reusable helpers: start
from maintainer intent, prefer the smallest maintainable solution, keep code
human-readable, document non-obvious effects and validate before success claims.
Repository evidence is durable memory; conversations are working context.
Keep small reviewable steps separate from intentional milestone closure.

Host changes follow Observe -> Explain -> Dry run -> Confirm -> Apply -> Verify
-> Remove. Privilege, persistent state and removal must be visible before use.
User-started affirmative action is required; installation, ACLs, OS identities
and synchronization settings retain their separately accepted boundaries.
Generic public recipes must never expose private governance or authenticated
state. Maintainer scope, compatibility, publication and risk acceptance remain
human-owned. A successful command is evidence, not proof of real-host safety.
